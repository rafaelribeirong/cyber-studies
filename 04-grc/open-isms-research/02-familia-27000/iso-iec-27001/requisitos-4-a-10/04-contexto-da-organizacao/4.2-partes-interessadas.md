# 4.2 - Compreensão das necessidades e expectativas das partes interessadas

**Status:** pesquisa inicial  
**Versão:** 0.1  
**Última revisão:** 22 de agosto de 2026  
**Autor:** Rafael Ribeiro

## Finalidade

Identificar as partes interessadas relevantes para o Sistema de Gestão de Segurança da Informação (SGSI), compreender seus requisitos relevantes e determinar quais desses requisitos serão tratados pelo sistema.

## O que deve ser determinado

A organização deve estabelecer:

1. quais partes interessadas são relevantes para o SGSI;
2. quais requisitos dessas partes são relevantes para segurança da informação;
3. quais requisitos serão tratados por meio do SGSI.

A existência de uma parte interessada não torna todas as suas expectativas requisitos do sistema. É necessário avaliar relevância e aplicabilidade.

## Exemplos de partes interessadas

- clientes;
- trabalhadores;
- direção e acionistas;
- fornecedores;
- prestadores de serviços;
- parceiros comerciais;
- autoridades e reguladores;
- organismos de certificação;
- titulares de dados pessoais;
- seguradoras;
- sociedade, quando aplicável.

## Tipos de requisitos

- requisitos legais e regulatórios;
- contratos;
- acordos de confidencialidade;
- níveis de serviço;
- requisitos de clientes;
- políticas corporativas;
- requisitos de grupos econômicos;
- compromissos assumidos voluntariamente.

## Mudança climática

A Emenda 1:2024 incluiu uma observação indicando que partes interessadas relevantes podem possuir requisitos relacionados à mudança climática. A organização deve verificar a existência e a relevância desses requisitos para o SGSI.

## Resultados esperados

- partes interessadas relevantes identificadas;
- requisitos relevantes registrados;
- aplicabilidade avaliada;
- definição dos requisitos tratados pelo SGSI;
- responsáveis pelo acompanhamento;
- atualização quando ocorrerem mudanças.

## Evidências possíveis

- matriz de partes interessadas;
- matriz de requisitos legais e contratuais;
- contratos e acordos;
- registros de requisitos de clientes;
- atas de reuniões;
- análise de contexto;
- Declaração de Aplicabilidade, quando houver relação;
- processos de monitoramento legal ou contratual.

A matriz é uma forma possível de organizar as informações, mas não é um modelo obrigatório.

## Perguntas de auditoria

- Como as partes interessadas relevantes foram definidas?
- Quais requisitos são relevantes para segurança da informação?
- Como foi determinada a aplicabilidade?
- Quais requisitos são tratados pelo SGSI?
- Quem acompanha alterações legais, contratuais e regulatórias?
- Como mudanças nos requisitos chegam aos processos do sistema?

## Possíveis deficiências

- lista de partes interessadas sem requisitos associados;
- inclusão indiscriminada de toda legislação;
- requisitos relevantes ausentes;
- falta de critérios de aplicabilidade;
- registros desatualizados;
- contratos não considerados;
- ausência de responsáveis pelo acompanhamento.
